# Kiri-ai — Project Guide

Digital version of **Kiri-ai: The Duel**, a 2-player samurai dueling card game, rendered in 3D with React Three Fiber. Current mode: **pass & play** on one device (turns driven by on-screen buttons). Designed so an async/multiplayer mode can be added later on top of the pure engine.

## Commands

```bash
yarn dev          # Vite dev server
yarn build        # tsc -b && vite build
yarn lint         # eslint (must stay clean)
yarn test         # vitest run — pure game-engine tests
yarn test:watch   # vitest watch
```

Stack: React 19, TypeScript 6, Vite 8 (rolldown), three 0.184 + @react-three/fiber 9 + drei, gsap (animations), leva (debug controls), vitest.

## Architecture

Strict separation between **pure game logic** (no React/Three) and **rendering**.

```
src/common/
  game/                # PURE engine — no React, no Three, fully unit-tested
    types.ts           # Stance, Team, Side, Slot, CardDef, PlayerState, GameState, GameAction, ActionResolution
    cards.ts           # CARD_DEFS, getCardDef, getEffect, distributeSpecials
    rules.ts           # board geometry (spaceToX), movementPriority, resolveAction (movement→attacks→damage)
    engine.ts          # createInitialState + reducer(state, action)
    engine.test.ts     # vitest suite covering the rulebook
  state/               # React binding over the engine
    GameProvider.tsx   # useReducer(reducer); exposes { state, dispatch }
    useGame.ts         # context hook
    selectors.ts       # derives CardView[] for rendering (faceUp / interactive / location) — NO string parsing in components
  layout.ts            # ALL visual layout constants + fan math. Each Leva folder's defaults live here in ONE well-defined object: DEFAULT_SCENE_FRAME, STAGE, STAGE_LAYERS, FLOOR, BATTLEGROUND, PLAYED_CARDS, DEFAULT_FAN, LOBBY, INTRO, GAME_HUD, SEAL_DISC
  hudPalette.ts        # HUD ink palette (INK, SEAL, TEAM_INK), team/stance kanji + Italian labels, kanjiNumeral
  cardAlpha.ts         # shared rounded-corner alpha-map texture for cards
  floorTexture.ts      # alpha gradient for the duel floor (its colour map is the shared 0-base paper)
  leaves.ts            # pure leaf-field math for the lobby's falling maple leaves — deterministic per-index spawn/pose, unit-tested, no React/Three
  mistTexture.ts       # procedural paper-white fog-band texture for the lobby mist (same module-level-build idiom as floorTexture.ts)
  hooks/               # useCardTextures (+ texture preload), useCardFlip; one leva hook per folder: useSceneFrame, useFanControls, usePlayedCardControls, useBattlegroundControls, useLobbyControls
  components/
    atoms/             # Pawn, BoardLine, CardModel, LifeSeal, SealDisc, StanceDiamonds, InkSplash, FitCamera, ParallaxLayer, Floor, Mist, FallingLeaves, IntroFlight, RevealGroup, InkStrokeButton, InkCanvas
    molecules/         # Card (dispatcher), MovementCard, RegularCard, HandCard, PlayerBanner, RoundMarker
    sections/          # Battlefield, Hand, GameHud, HandoffVeil, StrikeSplash, ConfirmButton, WinBanner, CardNameReveal, Stage, Scene, LobbyScene, InkLayer, InkTransition
App.tsx                # <GameProvider><Scene/></GameProvider>
main.tsx               # createRoot — NO StrictMode (see Gotchas)
```

Component hierarchy is by complexity: **atoms** (dumb primitives) → **molecules** (compose atoms + interaction) → **sections** (wired to game state). Molecules must not import from sections.

### Data model (no fragile string IDs)
A card is typed data, never a `team-card:side` string. The engine state holds `PlacedCard { cardId, side, revealed }`; rendering reads `CardView` objects from `selectors.ts`. The board is 5 spaces (index 0–4); red starts at 0, blue at 4; `spaceToX` maps index → world x.

### Scene & 3D staging (background + floor + interface)
`Scene` locks a **level front camera** (no orbit; `FitCamera` dollies on z to keep `SceneFrame` framed at any width), so the view is composed as flat, painter-ordered layers:

```
scenery (Stage, renderOrder −100…) → floor (renderOrder −10) → pieces (board/pawns z≈0) → cards (always-on-top)
```

- **Stage** (`sections/Stage` + `atoms/ParallaxLayer`): a sumi-e backdrop = full-frame PNG layers (`STAGE_LAYERS`) over the shared paper plate `0-base.jpeg`, fitted to the **top half** above the horizon (`HORIZON_FRACTION`). Layers keep NATIVE aspect (no stretch); each layer's `y` pulls the elements together so they all fit; depth = differential pointer-parallax + idle drift (faked, NOT real z-separation). Width is sized from the real visible width (`frameViewport`), NOT `frame.halfWidth` (which tracks the gameplay cluster and shrinks with the cards).
- **Floor** (`atoms/Floor`): the **bottom half** — the same `0-base` paper as a plane raked toward the camera (`tilt`), its far edge faded into the horizon via `floorTexture`'s alphaMap; it masks the scenery below the horizon.
- **Background art assets**: `public/images/backgroud/` (note the typo dir). `0-base.jpeg` = plain washi paper (backdrop base AND floor map); `1-sun` / `2-far-mountain` / `3-middle-mountain` / `4-near-mountain` / `4-tree` = transparent PNG elements. They were chroma-keyed from AI output by `scripts/cutout_layers.py` — Nano Banana fakes "transparency" as a baked checkerboard, so generate each element on a **solid green field** and key it out (never a checkerboard / never JPEG, which has no alpha).
- **Battleground** (`Battlefield` + `BoardLine`): board line + pawns, positioned by `BATTLEGROUND { x, y }`. Portrait: the vertical line lives in the band given by the pure `portraitLineBand` (between `hudReserve` at the top — minus the standing pawn's height, so the top samurai's head clears the DOM HUD — and `handReserve` at the bottom); samurai and the coloured marker spikes are scaled down there (`pawnScale`, `spikeScale`), and a full hand overlaps more (`PORTRAIT_FAN_MIN_STEP`, `fitHandFan`'s `minStepRatio`) before its cards shrink. The portrait card columns (played cards + `LandingZones`) hug the lateral viewport edges (`playedEdge`, measured to the visible card FACE) and turn toward the centre about Y (`playedTilt` → `rotationY` from `playedCardTransform`: outer edge toward the viewer, inner edge receding toward the battleline). Because those columns hug the edges, `CardNameReveal` in portrait drops the per-card labels and paints BOTH revealed names on one split stroke at the bottom (`InkStrokeLabel split` → registry `segment.both`: each half lit in its own tone; left half = left column's card). The line is **pure white** (`meshBasicMaterial`, `toneMapped:false`); the diamond markers are **raked onto the floor** (`diamondTilt` — match it to the floor `tilt`).

All scenery/floor meshes are **unlit** (`meshBasicMaterial`, `toneMapped:false`) so the painted colours stay exact (the scene has no lights at all). `<Stage/>` + `<Floor/>` render even with the interface off (`Game UI → showInterface`).

- **Lobby** (`sections/LobbyScene`): the menu backdrop re-stages the same Stage art with the maple tree pulled to the LEFT edge (enlarged, nearest depth; the tree is anchored to TWO view edges via the measured `LOBBY.treeAnchor` — mass centre `LOBBY.treeEdge` inside the LEFT edge, painted base `LOBBY.treeBottom` above the BOTTOM edge, drawn ABOVE the lobby floor as true foreground — the art is a full-frame panel with the tree far bottom-left inside it, so a raw panel offset would slide it off-screen — and the leaf emitter follows the tree through `LOBBY.treeCanopyOffsetX`) as the source the falling leaves detach from — leaf motion is pure math (`leaves.ts`, deterministic per-index spawn/pose; each leaf detaches at its own staggered birth and scales in over `growSeconds`, on a field clock zeroed when the choreography releases the leaves — the field populates from an empty canopy, never switching on mid-air) rendered as GPU-instanced sprites (`atoms/FallingLeaves`) drifting right and re-entering the canopy once they cross the floor line; `atoms/Mist` (`mistTexture.ts`) drifts fog bands over the horizon. PORTRAIT has its own composition (`LOBBY.portrait`): logo at the top, the panorama pulled up under it (horizon as a fraction of the VISIBLE height) and enlarged, the menu centred below; a full-view `PaperPlate` replaces the panel-sized paper layer (whose edge showed on tall screens), the floor reaches the visible bottom (`Floor bottomY`), and the leaf emitter follows the bottom-anchored tree down. The entry cinematic is ONE gsap timeline over the Stage layer materials (paint on far → near), which then releases the leaves and hands off to the DOM menu (Framer Motion delays from `INTRO`, `InkStrokeButton` strokes slashed on by the ink shader); it's skippable at any point — `registerSkip`/`finish`, guarded by a `done` ref so it fires exactly once whether via timeline completion or a tap. On game entry, `InkTransition` (PERSISTENT: mounted idle from the first lobby frame, its veil pipeline pre-compiled with `compileAsync`, canvas parked on `frameloop="demand"` between sessions — creating it on click froze the first second) slashes giant sumi strokes over the screen one over another, swaps the lobby for `Scene` underneath on full cover (`onCovered`), and holds until `Scene`'s `onReady` — fired only after a run of smooth frames (`ReadySignal`: 6 frames < 1/24 s, 2.5 s cap), so mount-time shader/texture hitches stay under the ink — sets `release`. Wall-clock SAFETY NETS make sure the sequence never hangs on GPU frames (a lost/stalled canvas): `InkTransition` forces `onCovered` / finishes on timers, `AppRoot` forces `release` after `READY_TIMEOUT_MS`, and the veil layer CSS-fades out when a session ends. PERFORMANCE: the veil shader evaluates a slash's full brush only behind a cheap per-pixel proximity `If` (TSL `Fn`), renders at DPR 0.75, the lobby canvas pauses (`frameloop="demand"`) while covered, and `InkLayer` only renders while it has strokes. Then the flood drains and the slashes dry at DIFFERENT times (shuffled `dryStart`/`dryDur` from `veilStrokes`) while `IntroFlight` — now an APPROACH: the fully-mounted duel (no staged board/hand) seen from a little farther/higher, gliding in from the moment it's ready — closes on the game view. `IntroFlight`'s end pose and `FitCamera`'s locked pose both come from the same `cameraPose(frame, aspect, fov)`, so the handoff between them has zero jump. **Rematch** (local NUOVA PARTITA): `GameProvider`'s `RESET_GAME` calls `onRematch` (from `AppRoot`) instead of resetting in place — AppRoot drops `covering` for one beat (`rematch: rearm`) to re-arm the persistent veil, slashes it in again (`cover`), and on full cover remounts engine + scene fresh (`match` in the GameProvider key), so the new duel replays the whole opening; `release` is held while a rematch runs (the OLD scene still reads as ready). Online keeps RESET_GAME → leave.

### In-game HUD (DOM overlay, Italian copy)
- **GameHud**: `PlayerBanner` ×2 (team kanji 赤/青 on a carved `SealDisc` — pure-CSS raised bevelled rim, recessed face, kanji in relief; "Seal Disc" Leva folder, also used big on the HandoffVeil — name, stance 天/地 as the cards print it (`atoms/StanceDiamonds`: 天 over 地 on team-coloured diamonds, stacked UNDER the disc, the stance taken solid, the other at 0.2 — no text label), one `LifeSeal` 命 per life — cut by an ink slash when lost) + `RoundMarker` (kanji numeral in a brushed ensō, no "ROUND" label, a "MENU" hint under it). Landscape: the phase caption (SCELTA DELLE CARTE…) floats on its own, centred, `GAME_HUD.phaseCaptionTop` of the viewport height down — apart from the ensō. Both orientations: red top-left, blue top-right, round centred; the corner vignettes follow the same sides. Over them a full-screen dark edge vignette (`atoms/ScreenVignette`, `EDGE_VIGNETTE_TEXTURE`, `GAME_HUD.edgeVignetteOpacity`, renderOrder 65: above the glows at 60, under landing zones/cards) darkens all four corners and shades the acting team's glow down too. PORTRAIT is compact: `PlayerBanner compact` drops the name (disc + stance diamonds under it / the life seals on one row centred on the disc, height `GAME_HUD.bannerHeightCompact`), the phase caption is dropped, sizes use `portraitScale`, and the vignettes shrink (`vignetteWidthPortrait` / `vignetteHeightPortrait`). Life/stance lag the engine by `GAME_HUD.hitLagMs` so a seal breaks when the blade lands, not at reveal. `pointer-events: none` — never steals a hand drag.
- **Duel opening** (`state/duelIntro.ts`, module store `lying → hud → turn`, forward-only, reset on `Scene` unmount): samurai lie flat with NO HUD/hand → they stand up → the HUD (+ corner vignette) animates in → the first turn begins (turn highlight, pawn marker, the hand rises). Driven by `Battlefield` (`useDuelIntroDriver`, it owns the stand-up timing); delays `GAME_HUD.introHudDelay` / `introTurnDelay`. On a hand-over the outgoing hand slides down and the incoming one rises only after the veil is tapped (`useHandoffPending`).
- **HandoffVeil** (pass & play only): opaque washi veil whenever the device changes hands (key `round-team`; not for round 1 red). Fully derived (lagged key + dismissed key), no setState in effects.
- **Hit feedback** (blood-red ink `GAME_HUD.hitInk`): on the exact attack beat (`attackBeat()` in `useResolutionControls`, shared with the pawns) `StrikeSplash` washes the struck player's screen edge (white flash on a clash); the struck player's `LifeSeal` cracks in two after `hitLagMs`. No ink on the pawn itself (the old blood cut was removed). Leva "Game HUD → ▶ Play hit" (`state/hitPreview.ts`) replays it on blue.
- **In-duel menu**: the round ensō (`RoundMarker onMenu`, with a small "MENU" hint; live once the HUD is in — the only HUD element that takes pointers) opens `QuitDialog` via the `state/quitMenu.ts` module store: a washi veil (zIndex 1420, under the duel `InkLayer`) asking "abbandonare il duello?" with ESCI (`leave()` → lobby; online it closes the room) / ANNULLA (also veil tap / Esc). `ConfirmButton` steps aside while it's open.
- **Closing beat** (`state/victoryReveal.ts`, module store, reset on `Scene` unmount): on game-over the killing blow plays, the loser's cut-out falls flat, and only then — `useVictoryRevealDriver` in Battlefield, at fall delay + `standDur` + `WIN_BANNER.afterFall` — does `shown` flip; `WinBanner` and the end-of-duel `ConfirmButton` (NUOVA PARTITA / MENU) wait for it.
- **WinBanner**: "VINCE IL …" + a 一本 (ippon) seal stamped after the title. PORTRAIT has its own screen (`PortraitVictory`): a washi veil at zIndex 1400 (UNDER the duel `InkLayer` 1450, so the title stroke and NUOVA PARTITA stay on top) → the winner's `SealDisc` stamped behind the stage like a rising sun, with an ink ripple → the winner's silhouette (its final stance; the white PNG flooded with the team colour by an SVG `feFlood`+`feComposite in SourceAlpha` filter — a CSS mask under a filtered parent is unreliable on Safari, paper rim via zero-blur drop-shadows) raised like a paper-theatre figure → the title in white on a team-coloured `InkStrokeLabel` → 一本 stamped on the seal's corner → a tally ("in N round · X vite rimaste").

## Game rules (as implemented in `rules.ts`)

Each round: both players place 2 cards face-down (`first` = closest to opponent = action 1, `second` = action 2), then reveal/resolve first, then second, then end-of-round.

**Action resolution order** (both reveal one card in the same slot):
1. **Movement before attacks.** Priority = `(stance==heaven ? +100 : 0) + typeRank`, with typeRank Charge(3) > Approach/Retreat(2) > Change-Stance(1). Higher priority moves first; cannot pass the opponent (stops on their space); equal priority = simultaneous "meet in the middle" splitting the gap (`floor(gap/2)`, matches rulebook Example 1). Change-Stance rotates the pawn without moving.
2. **Attacks** (simultaneous). Hit if attacker's stance ∈ card stances AND opponent sits on a target space (`attacker.space ± distance`). Wrong stance/out of range = feint. Both hit → **clash**, no damage. Kesa/Zan-Tetsu auto-switch stance after a valid attack.
3. **Counterattack** cancels the opponent's successful hit and deals damage; no-op if the opponent didn't hit.
4. **Damage**: 2 hits defeat a player → `phase: "game-over"`, `winner` set. Life shown = 2 − damage.

**End of round** (`END_ROUND`): first card returns to hand; second card is set aside for one round; the previously set-aside card returns; played specials are discarded (out of game); a special played second sets nothing aside that round.

Turn phases: `red-place → blue-place → ready → reveal-first → reveal-second → round-end → (next) | game-over`.

## Conventions

- **Leva controls**: every component/feature gets its **own named folder, collapsed by default** — `useControls("Name", schema, { collapsed: true })` — and its defaults come from **ONE well-defined object in `layout.ts`**, never scattered constants (e.g. `STAGE`, `FLOOR`, `BATTLEGROUND`, `PLAYED_CARDS`, `DEFAULT_FAN`, `DEFAULT_SCENE_FRAME`). The global `<Leva collapsed />` lives in `Scene`.
- **Layout constants** live only in `layout.ts` (zones, scales, fan geometry, offsets, scene-staging objects). `spaceToX` stays in `game/rules` because it's tied to the rules.
- **Layout changes are always animated (general rule)**: any element whose position can change because the layout around it changes (a column re-centring, a sibling appearing / leaving / resizing) gets Motion `layout="position"` with `LAYOUT_TRANSITION` (`src/common/motionPresets.ts`), inside a `LayoutGroup` spanning the region (so a change in one subtree re-measures siblings that didn't re-render) — it glides, never jumps. Reference: the lobby column (`LobbyColumn` = `LayoutGroup`; logo, `ScreenFade`, `Stagger` and its rows are `layout="position"`).
- **Card visibility** (face up/down, interactive) is decided centrally in `selectors.ts`, never re-derived inside card components.
- Keep `yarn lint`, `yarn build`, and `yarn test` green before considering work done.

## Gotchas / lessons learned

- **No React StrictMode** (`main.tsx`): its dev double-mount restarts the imperative gsap card animations mid-flight, causing a visible hitch in the hand cascade. All HandCard tweens also use `overwrite: true` so a mid-flight re-render replaces tweens instead of stacking them.
- **eslint-plugin-react-hooks 7.x is strict**: it forbids synchronous `setState` inside effects and reading `ref.current` during render. Prefer derived values, capture mount-only props in a ref, use `useMemo` for objects read during render, and remount-by-key for transient UI (see `CombatToast`).
- **Material disposal**: materials created with `new THREE.Material(...)` and passed via the `material={}` prop are NOT auto-disposed by R3F. Per-card materials are `dispose()`-d on unmount (`useCardTextures`, `MovementCard`); the invisible hit material is a single shared module constant (`RegularCard`).
- **Rounded card corners** come from a shared alpha-map cutout (`cardAlpha.ts`, `alphaTest` on faces, `alphaMap` on overlays), not from the GLB. Tune `RADIUS` there.
- **eslint flat config**: use `reactHooks.configs.flat.recommended` (not the legacy `recommended-latest`, whose `plugins` is a string array).
- The hand fan uses a fixed per-card step (`DEFAULT_FAN.cardStep`) for a tight, overlapping look; it's anchored to the bottom of the viewport (derived from `SceneFrame` + aspect via `frameViewport`, not R3F's lagged cached viewport) and only shrinks if it would overflow a narrow screen.
- **Cards are always-on-top**: opaque cards lose the depth test to a nearer *transparent* mesh (e.g. a floor pushed forward in z), because opaque renders before transparent. So `HandCard` makes every card mesh ignore depth (`depthTest:false`, `transparent:true`) and draw last (`renderOrder = 100 + z·100`, per-card so the fan still stacks right) — cards then sit above scenery/floor whatever the floor's z.
- **Turn change must not "reload"**: a shared Suspense fallback blanks everything inside it while new textures load. So card textures for **both teams** are preloaded (`useCardTextures` module-level `useLoader.preload`), and `Battlefield` / `Hand` have **separate** Suspense boundaries — passing the turn never suspends or blanks the scene.
- **Hand entry & exit animations**: `HandCard` cascades in (`entry`, rises from below) and out (`exit`, slides down off-screen). Exit needs a **presence layer** in `Hand`: cards that leave the fan *without* moving to a slot stay mounted as "ghosts" (mounted at their last transform) until their down-tween finishes, then are dropped via async timers — same lint-safe pattern as `CombatToast`.
- **Sumi ink = a TSL shader, not art** (`src/common/ink/`). Style target: action sumi-e (haboku/hatsuboku) — fast dry-brush slashes, solid black head splitting into bristle streaks (kasure) toward the tip/flanks, flung droplets, pale wash beside the black. Each effect is a BRUSH STROKE in its own frame (`s` along the gesture, `n` across): pressure profile → bristle noise in `n` stretched along `s` → ink load falling along `s`/`|n|` vs paper tooth → droplets on an anisotropic cell grid → wash whose edge alone evolves with `time` (dry-brush marks stay put). Rendered by `WebGPURenderer` (WebGPU, falls back to WebGL2 — TSL compiles to both) in dedicated transparent canvases (`atoms/InkCanvas`, ortho, 1 unit = 1 CSS px); the game/lobby scenes stay on WebGL. **Lobby screen transitions**: each screen/view is a keyed `atoms/Stagger` (rows enter one after another out of a soft blur, and LEAVE the same way in reverse, bottom row first); a row's timing reaches the ink through `InkDelayContext` (`ink/inkDelay.ts`, `{enter, exit}` → registry `delay` / `exitDelay`), so each stroke is laid as its row arrives and — detected via Motion `useIsPresent` → registry `leaving` — runs back tip→head as its row leaves. Nothing disappears instantly: a nested `AnimatePresence` must set `propagate`, or the parent's exit removes it without its cascade. **Buttons — every button in the app is an `InkStrokeButton`** (a two-option choice is ONE stroke: `InkSegmentedStroke`, whose selected half takes its tone while the other goes ghost — `segment` on the registry entry, `segOn/segActive` uniforms) (lobby menu AND the duel's `ConfirmButton`): it only REGISTERS its element in `ink/inkRegistry` (external store); `sections/InkLayer` draws one stroke per entry (lobby: between `LobbyScene` and the column, by DOM order; duel: mounted in `Scene` at `zIndex` 1450, just under the button overlay), re-reading the button rect + effective DOM opacity every frame; labels stay DOM on top. **Veil**: `InkTransition` = 6 giant combed slashes (`veilStrokes`, pure + coverage-tested) + a closing flood → `onCovered`; on release it dries into streaks and UNMOUNTS. Look params are shared live uniforms (`INK_LOOK`, "Ink" Leva folder, defaults `INK` in layout.ts). Uniforms are mutated in `useFrame` via the mesh ref (`inkUniforms(material)`), never via `useMemo` values (react-hooks immutability rule). No WebGPU/WebGL2 → CSS stand-ins. The old mask PNGs in `public/images/intro/` (`stroke-*`, `veil-*`, `wipe-*`) and `scripts/ink_masks.py` are no longer used at runtime.
- **Everything is UNLIT — no lights, no environment map**: cards included (`useCardTextures` → `MeshBasicMaterial`, `toneMapped:false`); a glossy card face mirrored the HDRI sky and washed the art out at phone angles. The old `atoms/Lights` (ambient + point + a self-hosted HDRI) was removed with it. If lighting ever comes back, never use a drei `Environment preset` (it streams from an external CDN, ~10 s / hangs offline) and keep any env map in its OWN `<Suspense>` — outside it, it suspended the whole duel canvas and the veil sat on black.
- **Paper cut-out samurai** (`atoms/Pawn`, `PAPER_CUTOUT`, "Paper Cutout" Leva folder with a "play stand-up" button): each stance is a stack — dark offset edge (sheet thickness) → cream rim (silhouette scaled up) → tinted silhouette — inside a hinge group at the feet, plus a procedural contact-shadow ellipse. Entrance: lying back on the floor (`lieAngle`) until `standing`, then raised slowly like a paper-theatre figure (two sine-eased beats: a long lift drifting just past vertical, one soft ease back — no spring; the second samurai starts once the first is halfway up). `standing` = the veil has actually OPENED (`ink/veilSignal`, set when the drying passes `VEIL_OPEN_AT`; the drying is back-loaded because overlapping slashes uncover a spot only once all have dried). The veil's own clock is accumulated, capped frame time, so a hitch never skips the drying. Defeat (both orientations): the loser's cut-out FALLS back flat — the stand-up in reverse (settle undone, then the long lift reversed down to `lieAngle`, shadow fading) — via Pawn `fallen`/`fallDelay`, set by Battlefield after the killing blow's attack beat; a new duel raises it again. Leva "Paper Cutout → play fall" previews it on blue (`fallTick`), then stands it back up. Every landed hit also makes the struck cut-out TOTTER back and forth on its feet, as if about to fall (a few damped swings about x — `swayAngle`/`swayDur`) at the attack beat; it runs on its own `swayRef` group inside the hinge, so it composes with the lie/stand/fall tweens on the hinge instead of cancelling them. Overlap: the cut-outs ignore depth, so each draws its layers in its OWN renderOrder band (`PAWN.stack`, `layerOrder`) — a close pair stacks as two whole sheets (landscape red over blue, portrait the nearer bottom team on top), and a swaying figure drops behind the other until it's upright again, so they never cut through each other. "Game HUD → ▶ Play hit" sways blue too (`hitTick`). **Permanent sword cut** (`src/common/pawnCut.ts`): at the blow a thin TRIANGULAR notch is carved into the struck figure, coming from ABOVE on its OUTER side (its back, away from the opponent) and running down into the body at `cutAngle` (figure space faces +x, so the back is −x for both teams/layouts) — its wide base lies outside the figure, so it enters from the edge already open and tapers to a point just past the body column: a notch like the card art, never a split — and stays, in both stances; the killing blow widens it (`cutDeath`). No extra meshes: `withCut` patches each paper layer's shader (edge, rim, silhouette × both stances) to clear the wedge, in a shared FIGURE space (stance group: body column x = 0, feet y = 0) synced per frame by `syncCutLayer`; the silhouette's notch is wider than the rim's (`cutRim`) so white paper edges the cut. Tunables `PAPER_CUTOUT.cut*` ("Paper Cutout" Leva); "▶ Play hit" previews it on blue, then mends it.
- **Framer Motion owns `transform` on animated elements**: once a `motion.*` element animates any transform-adjacent value (`x`, `scale`, `rotate`, …) via `animate`/`variants`, Framer Motion takes over the whole `transform` string on every render — a plain `style.transform` STRING on the same element is silently discarded. Put every transform component that needs a fixed value inside the animated value set too (e.g. a fixed `rotate` lives in `variants`, not `style`). Exception: independent transform props passed directly in `style` (`rotate`, `x`, `y`, `scale`, …) ARE picked up as Motion-managed values and compose fine alongside `animate`/`variants` targets on the same element (see `InkTransition`'s stroke `style.rotate` coexisting with its animated `x`). Related gotcha: a changed `transition.delay` never restarts a Motion animation that is already pending, and re-resolving the same variant to identical targets is a no-op (`protectedKeys`) — so the lobby menu's paint-on is STATE-driven (Lobby's `beat` counter flips each element hidden → painted, a target-changing switch), not delay-scheduled.
- **Online mode & TURN**: multiplayer is Trystero P2P (WebRTC, Nostr signaling) owned by `src/common/net/SessionProvider.tsx`. PC↔mobile needs a TURN relay (carrier CGNAT blocks direct paths). Credentials are short-lived Cloudflare ones minted by `api/turn-credentials.ts` — a Vercel serverless function (works in this Vite project without Next; env `TURN_KEY_ID` + `TURN_KEY_API_TOKEN`, server-side only, never `VITE_*`). Client resolution chain in `src/common/net/iceServers.ts`: `VITE_ICE_SERVERS` override → `/api/turn-credentials` (cached until near TTL) → static `VITE_TURN_*` → STUN-only. `yarn dev` does NOT serve `/api` — test TURN locally with `vercel dev` or the `VITE_*` fallbacks in `.env.local`. Signaling relays are **pinned** (`RELAY_URLS` in SessionProvider): Trystero's hash-sampled defaults often land on flaky community relays whose sockets open but drop events. Connection health (relay count, TURN source, ICE state via a wrapped `RTCPeerConnection`) is shown on-screen in the lobby waiting panel (`net/diagnostics.ts`) because mobile has no console. Room keywords are **normalized (trim+lowercase) in SessionProvider**: the topic hash is case-sensitive, mobile keyboards auto-capitalize, and the display font renders everything uppercase so the mismatch is invisible.

## Testing

`game/engine.test.ts` exercises the rulebook (movement priority, the meet-in-the-middle example, stance/feint, clash, counter, win condition, end-of-round card rotation). The engine is pure, so add a test there for any rule change before touching the UI.
